# internal/schema

Schema comparison: load the full structure of a database, list the changes that make a target match a source, turn them into DDL for the target engine and run it. The source is the reference; nothing here changes the source. Does not import Wails.

Source and target must be the same engine (MariaDB counts as MySQL). Types and defaults are copied as text, so there is no cross-engine type mapping.

## Files

| File | Contents |
|---|---|
| `schema.go` | `Table` (table + columns + primary key + indexes), `Load` |
| `diff.go` | `Kind`, `Change`, `Diff` (pure function, no database access) |
| `normalize.go` | `normalizeType`, `normalizeDefault`: equality only, DDL keeps the original text |
| `ddl.go` | `Step`, `Script` (changes to statements), `Apply` (one transaction), `TransactionalDDL`, shared SQL builders |
| `ddl_postgres.go`, `ddl_mysql.go`, `ddl_sqlserver.go`, `ddl_sqlite.go` | one generator per engine |

## Matching

| Object | Matched by | Different when |
|---|---|---|
| Table | `Schema` + `Name` (exact) | — (missing on one side) |
| Column | `Name` (exact) | normalized type, `Nullable`, `AutoIncrement`, or normalized default differ. `Position` is ignored |
| Primary key | — | column list differs (nil and empty are equal) |
| Index | `Name` (exact) | `Columns`, `Unique` or `Constraint` differ |

A changed index becomes `DropIndex` + `AddIndex`; a renamed column or table becomes drop + add (no rename detection).

## Order

`Diff` never reorders its inputs and returns:

1. `AddTable` (by schema, name). `Create` holds the whole source table.
2. Changes to tables on both sides, grouped by table, in phases:
   `DropIndex` → `AddColumn` → `AlterColumn` → `AlterPrimaryKey` → `DropColumn` → `AddIndex`.
   Indexes are dropped before the columns they use; columns exist before keys and indexes need them.
   Added columns come in source position order, so `After` always names a column that already exists or was added earlier.
3. `DropTable`.

`Destructive` is set on `DropTable`, `DropColumn` and on `AlterColumn` when the type changes. Nullability and default changes are not marked (setting `NOT NULL` fails on existing NULLs rather than losing data).

## Normalization

| Case | Example | Rule |
|---|---|---|
| Type case and spacing | `VARCHAR(20)` vs `varchar(20)` | lowercase, collapse spaces |
| MySQL integer display width | `int(11)` vs `int` | drop `(n)` after integer types (also `tinyint(1)`) |
| SQL Server parentheses | `((0))` | strip parentheses around the whole expression |
| PostgreSQL casts | `'guest'::character varying` | strip a trailing top-level `::type` (not `nextval('s'::regclass)`) |
| Expression case | `CURRENT_TIMESTAMP` | lowercase outside string literals |
| MariaDB vs MySQL | `current_timestamp()` | → `current_timestamp` |

## DDL

`Script(d, dst, changes)` takes the target's current structure and any subset of `Diff`'s changes (in `Diff` order). It replays them on a copy of `dst`, so each step is generated against the table as the earlier steps left it (SQLite rebuilds depend on this). `dst` is not modified. A change that cannot be applied gets `Step.Unsupported` and no SQL, and later steps are generated as if it had not been selected.

| Change | PostgreSQL | MySQL / MariaDB | SQL Server | SQLite |
|---|---|---|---|---|
| Add table | `CREATE TABLE` with PK and `UNIQUE` constraints inline, then `CREATE INDEX` | same | same | same |
| Add column | `ADD COLUMN` | `ADD COLUMN … AFTER x` / `FIRST` | `ADD` | `ADD COLUMN`; rebuild if `NOT NULL` without default or the default is not a constant |
| Drop column | `DROP COLUMN` | `DROP COLUMN` | drop the default constraint, then `DROP COLUMN` | `DROP COLUMN`; rebuild if it is in the PK or a `UNIQUE` constraint |
| Alter column | `DROP IDENTITY`, `TYPE … USING c::type`, `SET/DROP DEFAULT`, `SET/DROP NOT NULL`, `ADD … IDENTITY` (only what changed) | `MODIFY COLUMN` with the full definition | drop default, `ALTER COLUMN type [NOT] NULL`, re-add default (only around what changed); identity change unsupported | rebuild |
| Primary key | drop the PK constraint (name looked up in a `DO` block), `ADD PRIMARY KEY` | one `DROP PRIMARY KEY, ADD PRIMARY KEY` | drop the PK constraint (name looked up), `ADD PRIMARY KEY` | rebuild |
| Add / drop index | `CREATE INDEX` / `DROP INDEX schema.ix`; constraints via `ADD/DROP CONSTRAINT` | `CREATE INDEX` / `DROP INDEX ix ON t` | `CREATE INDEX` / `DROP INDEX ix ON t`; constraints via `ADD/DROP CONSTRAINT` | `CREATE INDEX` / `DROP INDEX`; `UNIQUE` constraints rebuild |

Engine details:

- PostgreSQL: an integer column whose default is `nextval('…'::regclass)` is created as `serial` / `bigserial` / `smallserial`, because the source's sequence does not exist on the target. Identity columns are created `GENERATED BY DEFAULT AS IDENTITY` (`ALWAYS` is not distinguished).
- MySQL: expression defaults are wrapped in parentheses (`DEFAULT (uuid())`); MySQL reports them bare. `AUTO_INCREMENT` columns keep their key because the PK change is one statement.
- SQL Server: default and PK constraint names are generated by the server, so the statements look them up (`sys.default_constraints`, `sys.key_constraints`) and drop them with `sp_executesql`.
- SQLite rebuild: `CREATE TABLE "t__synccraft_new"`, copy the columns both versions share, `DROP TABLE "t"`, rename, recreate indexes.

`Apply` runs all statements in one transaction and refuses steps marked unsupported. PostgreSQL, SQL Server and SQLite roll everything back on failure; MySQL commits each DDL statement implicitly (`TransactionalDDL` is false), so statements before a failure stay applied and the UI must say so.

## Limits

- Same engine only (see above).
- Auto-generated constraint names (SQL Server `UQ__users__…`, `PK__…`) differ between databases and show up as index changes.
- Altering a column that an unchanged index uses fails on SQL Server; `Diff` does not drop and recreate that index.
- Not compared: foreign keys, check constraints, views, triggers, collations, comments, generated columns (created as plain columns), MySQL `ON UPDATE CURRENT_TIMESTAMP` (see `internal/dialect` "Not covered yet").
- A SQLite rebuild recreates only what is modelled: foreign keys, `CHECK`, triggers and `AUTOINCREMENT` on that table are lost.
- Identity and serial columns start numbering at 1 on a new table; existing sequences are not synced.
- With binary logging on, MySQL refuses `ADD COLUMN … DEFAULT (uuid())` and similar non-deterministic defaults on a non-empty table (error 1674).

## Tests

Plain `go test` covers `Diff`, normalization, the statement text per engine, unsupported cases, and a full SQLite round trip. The round trip (`roundTrip` in `ddl_test.go`) loads both sides, applies every change to the target, and expects a second `Diff` to be empty; it also checks that rows survive.

PostgreSQL, MySQL and SQL Server run the same round trip with `-tags integration`, each in two throwaway databases:

```sh
podman compose -f dev/docker-compose.yml up -d pg-src mysql-src mssql
go test -tags integration ./internal/schema/...
```
