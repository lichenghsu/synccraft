# build

Wails v3 build configuration, generated by `wails3 init` and committed. Builds run through [Task](https://taskfile.dev): the root `Taskfile.yml` dispatches by `GOOS` to the per-platform `Taskfile.yml` here.

## Layout

| Path | Contents |
|---|---|
| `config.yml` | App info (name, identifier, version, …) and `wails3 dev` settings |
| `Taskfile.yml` | Shared tasks: frontend build, binding generation, icon generation (namespace `common:`) |
| `appicon.png` | 1024×1024 source icon, converted to each platform's format at build time |
| `darwin/` | macOS: Info.plist, icons, DMG assets, signing and notarization tasks |
| `windows/` | Windows: version info, manifest, NSIS, MSIX |
| `linux/` | Linux: `.desktop`, AppImage, nfpm (deb / rpm / Arch) |
| `docker/` | Dockerfile for cross-compiling (`wails3 task common:setup:docker`) |
| `ios/`, `android/` | Mobile platforms (experimental in Wails, currently unused) |

## Common commands

```bash
wails3 build                         # current platform → bin/
wails3 package                       # installer for the current platform
GOOS=windows wails3 build            # cross-compile for Windows (CGO=0, no Docker needed)
wails3 task darwin:package:universal # macOS universal (must run on a Mac)
wails3 task --list                   # list all tasks
```

## Changing app info

1. Edit `info:` in `config.yml`.
2. Run `wails3 task common:update:build-assets` to write the info into each platform's files.
3. This command **overwrites** manual edits in the platform files: commit first, then review with `git diff build/`.

> `wails3 init`'s `-product*` flags are not written to `config.yml` (v3.1.0), so it was edited by hand to match the platform files.

## Upgrading Wails

Upgrading the CLI does not update this folder. After a minor upgrade, run `common:update:build-assets` to regenerate from the new templates, then re-apply your customizations.
